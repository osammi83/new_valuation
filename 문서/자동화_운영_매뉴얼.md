## 📋 자동화 개요

UP Valuation은 3가지 정기 작업으로 구성되며, 모두 Windows Task Scheduler에 등록됩니다.

| 작업명 | 빈도 | 시간 | 담당 스크립트 | 목적 |
|--------|------|------|-------------|------|
| **UPValuation-Daily** | 매일 | 08:30 | run_daily.ps1 | 일일 리포트 생성 |
| **UPValuation-EPS-Monthly** | 월 1회 | 1일 08:00 | run_eps_cache_refresh.ps1 | EPS 캐시 갱신 |
| **UPValuation-Assumptions-Monthly** | 월 1회 | 1일 08:10 | run_assumptions_refresh.ps1 | assumptions 동기화 |

## 🚀 초기 설정 (1회만 수행)

### Step 1: DART API 키 환경변수 설정

```powershell
# PowerShell (일반 또는 관리자)
Set-Location "d:\00.개발\03.new_valuation"
powershell -ExecutionPolicy Bypass -File .\set_dart_api_key_env.ps1 -Scope User
```

프롬프트가 나타나면 본인 DART API 키를 입력합니다. 키 값은 파일에 적지 말고 발급받은 값을 그대로 붙여 넣습니다.

### Step 2: Google Drive 서비스 계정 연결

이 단계는 GitHub Actions가 만든 CSV를 내 Google Drive에 자동 저장하기 위한 설정입니다.

#### 2-1. Google Cloud에서 서비스 계정 만들기

1. Google Cloud Console에 로그인합니다.
2. 프로젝트를 하나 새로 만들거나 기존 프로젝트를 엽니다.
3. `API 및 서비스`에서 `Google Drive API`를 사용 설정합니다.
4. `IAM 및 관리자 > 서비스 계정`으로 이동합니다.
5. 새 서비스 계정을 생성합니다.
6. 역할은 우선 `편집자(Editor)` 이상으로 줍니다.
7. 서비스 계정 키를 생성하고 JSON 파일을 다운로드합니다.

#### 2-2. JSON 키 파일 저장

1. 다운로드한 JSON 파일을 프로젝트의 `keys` 폴더에 둡니다.
2. 예: `d:\00.개발\03.new_valuation\keys\service_account.json`
3. 파일명은 짧고 고정된 이름으로 유지합니다.

#### 2-3. Google Drive 폴더 공유

1. 업로드할 Google Drive 폴더를 하나 정합니다.
2. 폴더를 열고 `공유`를 클릭합니다.
3. JSON 파일 안의 `client_email` 값을 복사합니다.
4. 그 이메일을 Drive 폴더에 `편집자` 권한으로 공유합니다.
5. 브라우저 주소에서 폴더 ID를 복사합니다.
   - 예: `https://drive.google.com/drive/folders/폴더ID`

#### 2-4. 설정값 입력

`up_valuation_config.json` 또는 환경변수에 아래 값을 넣습니다.

| 항목 | 의미 | 예시 |
|---|---|---|
| `enableGoogleDriveUpload` | Drive 업로드 사용 여부 | `true` |
| `googleDriveFolderId` | 업로드 대상 폴더 ID | `1AbC...` |
| `googleServiceAccountJsonPath` | 서비스 계정 JSON 경로 | `d:\00.개발\03.new_valuation\keys\service_account.json` |

#### 2-5. 확인

```powershell
Set-Location "d:\00.개발\03.new_valuation"
. .\check_drive_config.ps1
```

정상이라면 다음 항목이 보여야 합니다.

- `Google Drive folder ID is set`
- `Service account JSON file exists`
- `Service account email = ...`
- `Google API Python libraries are installed`

### Step 3: KRX 로그인 정보 등록

KRX 로그인 정보는 KRX 수집/보조 작업에서 쓰이며, 로컬 Windows 환경변수로 저장합니다.

#### 3-1. 스크립트 실행

```powershell
Set-Location "d:\00.개발\03.new_valuation"
.\set_krx_login_env.ps1 -Scope User
```

#### 3-2. 입력값

- `KRX ID 입력`: KRX 로그인 ID
- `KRX Password 입력`: KRX 로그인 비밀번호

#### 3-3. 저장 방식

- 현재 PowerShell 세션에도 즉시 반영됩니다.
- 기본 `User` Scope는 현재 사용자 계정에 저장됩니다.
- 새 PowerShell 창을 열어도 유지됩니다.

#### 3-4. 확인

```powershell
echo $env:KRX_ID
[Environment]::GetEnvironmentVariable('KRX_ID','User')
[Environment]::GetEnvironmentVariable('KRX_PW','User')
```

#### 3-5. 주의사항

- 이 값은 GitHub Secrets나 프로젝트 파일에 평문으로 남기지 않습니다.
- `Machine` Scope는 관리자 권한이 필요할 수 있어, 보통 `User` Scope로 시작합니다.
- KRX 값이 비어 있으면 KRX 관련 수집/보조 로직이 실패할 수 있습니다.

### Step 4: Python 경로 환경변수 설정 (선택, 권장)

```powershell
[Environment]::SetEnvironmentVariable(
    'UP_VALUATION_PYTHON',
    'd:/00.개발/.venv/Scripts/python.exe',
    'User'
)
```

### Step 5: 스케줄러 자동 등록

```powershell
# 관리자 권한 PowerShell
Set-Location "d:\00.개발\03.new_valuation"
.\install_automation.ps1
```

설치 완료 확인:
```

✓ Task 'UPValuation-EPS-Monthly' registered successfully
```

## 📅 정기 작업 상세 설명

### 작업 1: UPValuation-Daily (매일 08:30)

**역할:** 일일 리포트 생성 및 분석

**실행 내용:**
1. `preprocess_daily_updates.py` 실행
   - DART 당일 공시 스캔 (실적, 잠정 관련)
   - 주식수 변동 감지 및 EPS 리밸런싱
   - Forward EPS 자동 채움

2. `build_daily_report.py` 실행
   - 시장 레짐(BULL/BEAR) 판단
   - 가격, 기술 지표 계산
   - 밸류에이션 분석
   - 점수 종합
   - 기본 Compact 출력(핵심 4개 파일) 생성
   - 필요 시 Full 출력(상세 확장 파일 전체) 지원
   - 문서 컬럼 사전 파일(없을 때만) 생성
   - 레거시 10일 타임라인 파일 자동 정리

**생성 파일:**
- `output/상세리포트_YYYY-MM-DD.csv` (상세, 45컬럼)
- `output/종목선정_핵심근거_YYYY-MM-DD.csv` (초보자용 선정근거 통합: 신호승률/기대값/거래량지표 포함) ⭐
- `output/최종매수_30일타임라인_YYYY-MM-DD.csv` (최종매수후보 30일 타임라인)
- `output/최종매수_전일비교_YYYY-MM-DD_vs_YYYY-MM-DD.csv` (전일 대비 변화)

**Full 모드 추가 파일(선택):**
- `output/관심종목요약_YYYY-MM-DD.csv`
- `output/진입후보요약_YYYY-MM-DD.csv`
- `output/신호성과요약_YYYY-MM-DD.csv`
- `output/신호발생상세_YYYY-MM-DD.csv`
- `output/종목선정_판단보조_YYYY-MM-DD.csv`
- `output/신호지표_초보자가이드_YYYY-MM-DD.csv`
- `output/종목선정_우선검토_YYYY-MM-DD.csv`

**문서 자산 파일:**
- `문서/up_column_dictionary_ko.csv` (컬럼정의, 파일이 없을 때만 생성)

**소요 시간:** 약 1~2분 (800종목 기준)

**로그 위치:** `run_daily.log` (또는 Task Scheduler 로그)

## 🛠️ 수동 실행 (즉시 테스트)

### 테스트 실행 (소량, 권장)

```powershell
Set-Location "d:\00.개발\03.new_valuation"

# 1단계: EPS 캐시 갱신 (소량)
.\run_eps_cache_refresh.ps1 --force --limit 50

# 2단계: assumptions 동기화
.\run_assumptions_refresh.ps1 --limit 50

# 3단계: 일일 리포트 (소량)
.\run_daily.ps1 --limit 50 --period 6mo
```

### 완전 실행 (전체 800종목)

```powershell
# EPS 캐시 갱신
.\run_eps_cache_refresh.ps1 --force

# assumptions 동기화
.\run_assumptions_refresh.ps1

# 일일 리포트
.\run_daily.ps1 --period 6mo
```

### 명령행 옵션

| 옵션 | 설명 | 예시 |
|------|------|------|
| `--limit N` | 첫 N개 종목만 처리 | `--limit 50` |
| `--force` | 캐시 강제 갱신 | `--force` |
| `--period` | 기술지표 조회 기간 | `--period 6mo` |

## ☁️ Google Drive 자동 업로드 설정

이 섹션은 두 가지 실행 환경으로 나눠서 봐야 합니다.

- 로컬 실행용: 내 Windows PC에서 직접 돌릴 때
- GitHub Actions 실행용: GitHub runner에서 돌릴 때

### 1) 로컬 실행용 설정

#### 1-1. 사전 준비

1. Google Cloud Console에서 서비스 계정 생성
2. Drive API 활성화
3. 서비스 계정 키(JSON) 발급
4. 업로드 대상 Google Drive 폴더를 서비스 계정 이메일과 공유(편집 권한)
5. 폴더 URL에서 folderId 확인

#### 1-2. 설정 파일 입력

로컬 PC에서 직접 실행할 때는 JSON 파일이 실제로 있는 경로를 넣습니다.

```json
{
   "pythonPath": "d:/00.개발/.venv/Scripts/python.exe",
   "enableGoogleDriveUpload": true,
   "googleDriveFolderId": "여기에_폴더ID",
   "googleServiceAccountJsonPath": "d:/00.개발/03.new_valuation/keys/service_account.json"
}
```

#### 1-3. 대체 방식(환경변수)

```powershell
[Environment]::SetEnvironmentVariable('GOOGLE_DRIVE_FOLDER_ID','여기에_폴더ID','User')
[Environment]::SetEnvironmentVariable('GOOGLE_SERVICE_ACCOUNT_JSON','d:/00.개발/03.new_valuation/keys/service_account.json','User')
```

#### 1-4. 동작 방식

- `run_daily.ps1` 실행 시 `build_daily_report.py` 이후 `upload_to_google_drive.py` 자동 실행
- 같은 이름 파일이 Drive에 있으면 업데이트, 없으면 신규 업로드
- 인증값이 없으면 업로드 단계는 자동 스킵되고 본 리포트 생성은 정상 진행

### 2) GitHub Actions 실행용 설정

GitHub Actions에서는 내 PC의 `d:\...` 경로를 직접 쓸 수 없습니다. 대신 서비스 계정 JSON 내용을 Secret으로 저장하고, 워크플로우 실행 중 runner 안에 임시 파일로 만들어 사용합니다.

#### 2-1. 사전 준비

1. Google Cloud Console에서 서비스 계정 생성
2. Drive API 활성화
3. 서비스 계정 키(JSON) 발급
4. 업로드 대상 Google Drive 폴더를 서비스 계정 이메일과 공유(편집 권한)
5. GitHub 저장소 Secrets에 서비스 계정 JSON 내용을 등록
6. GitHub 저장소 Secrets 또는 workflow env에 `GOOGLE_DRIVE_FOLDER_ID` 등록

#### 2-2. 설정 원칙

- `googleDriveFolderId`는 GitHub runner가 접근할 폴더 ID를 의미합니다.
- `googleServiceAccountJsonPath`는 runner 안에서 임시로 생성한 JSON 파일 경로를 의미합니다.
- 로컬 PC 경로를 그대로 적는 방식은 GitHub Actions에서 동작하지 않습니다.

#### 2-3. 예시

GitHub Actions에서 JSON Secret을 파일로 풀어쓴 뒤 그 임시 경로를 사용합니다.

```yaml
- name: Write service account json
   run: |
      $jsonPath = Join-Path $env:RUNNER_TEMP 'service_account.json'
      Set-Content -Path $jsonPath -Value '${{ secrets.GOOGLE_SERVICE_ACCOUNT_JSON }}'
      echo "GOOGLE_SERVICE_ACCOUNT_JSON_PATH=$jsonPath" >> $env:GITHUB_ENV
```

그 다음 Python이나 PowerShell에서 `GOOGLE_SERVICE_ACCOUNT_JSON_PATH`를 `googleServiceAccountJsonPath`로 넘깁니다.

#### 2-4. 동작 방식

- GitHub Actions가 CSV를 생성한다.
- 워크플로우가 Drive 업로드 단계를 실행한다.
- 서비스 계정 JSON은 runner의 임시 파일로만 존재한다.
- 공용 Streamlit은 결과를 읽기만 하고, 실제 업로드는 GitHub Actions가 담당한다.

## 📱 핸드폰에서 실행/확인

### 권장 운영 방식

1. 실행은 노트북(스케줄러)에서 지속 운영
2. 결과 확인은 핸드폰 Google Drive 앱에서 확인
3. 필요 시 노트북 원격접속(Chrome Remote Desktop 등)으로 수동 실행

### 핸드폰 직접 실행이 어려운 이유

- 현재 파이프라인은 Python + Windows PowerShell + 로컬 스케줄러 기반
- 모바일 OS에서는 동일 실행환경 구성이 어렵고 자동화 안정성이 낮음

## 🔧 트러블슈팅 & 해결 방법

### 문제 1: 파일이 생성 안 됨

**증상:** output/ 폴더에 새 파일이 없음

**진단:**
```powershell
# 수동 실행으로 에러 확인
Set-Location "d:\00.개발\03.new_valuation"
.\run_daily.ps1 --limit 10
```

**해결 방법:**

| 원인 | 해결책 |

### 문제 2: PermissionError (파일 잠금)

**증상:** `output/*.csv` 저장 시 Permission denied

**원인:** 엑셀에서 동일 CSV를 열어 둔 상태

**해결:**
1. 열려 있는 CSV 닫기
2. `run_daily.ps1` 재실행
3. 자동 fallback 파일(`*_locked_HHMMSS.csv`)이 생성되면 해당 파일로 우선 확인

### 문제 3: 최종매수후보가 0개

**설명:**
- 시장 조건에 따라 당일 최종매수후보가 0개일 수 있음
- 이 경우에도 `최종매수_30일타임라인_*.csv`는 빈 스키마로 생성되는 것이 정상
|------|--------|
| `universe.csv` 손상/공란 | `universe.csv` 삭제, 다음 실행 시 자동 재생성 |
| `eps_cache.csv` 손상 | `.\run_eps_cache_refresh.ps1 --force --limit 10` |
| Python 경로 오류 | `$env:UP_VALUATION_PYTHON` 재설정 |
| 네트워크 오류 | VPN/인터넷 연결 확인 |

```powershell
# EPS 캐시 상태 확인
gc .\eps_cache.csv | head -10
```

| Naver 스크래핑 페이지 구조 변경 | 일주일 기다려보기 (수정 예정) |

```powershell
# Task Scheduler 확인
Get-ScheduledTask -TaskName "UPValuation-*"
```

**해결 방법:**

```powershell
# 1. 관리자 권한으로 재등록

.\install_automation.ps1

# 2. 또는 수동으로 작업 실행
Start-ScheduledTask -TaskName "UPValuation-Daily"

# 3. 또는 PowerShell에서 직접 실행
.\run_daily.ps1
```

## 🔐 보안 & 유지보수

### DART API 키 보안

✅ **권장 (현재 구현)**
- Windows 환경변수 (User 스코프)에 저장
- 코드/CSV 파일에 하드코딩 안 함

❌ **비권장**
- CSV에 키 저장
- 코드 내 직접 입력
- 기본값으로 방치

### 백업 정책

월 1회 이상 아래 파일 백업 권장:

```
📁 백업 대상
├── assumptions.csv (수동 입력값)
├── universe.csv (유니버스 정의)
├── eps_cache.csv (EPS 캐시)
└── output/*.csv (월간 보고서)
```

```powershell
# 자동 백업 스크립트 예시
$BackupDir = "d:\00.개발\03.new_valuation\backups\$(Get-Date -Format 'yyyy-MM')"
if (-not (Test-Path $BackupDir)) { mkdir $BackupDir }
Copy-Item "assumptions.csv", "eps_cache.csv" $BackupDir -Force
```
