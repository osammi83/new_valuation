# UP Valuation 신규 개발/재구축 매뉴얼

작성일: 2026-04-18  
최종 업데이트: 2026-04-24  
문서 버전: 2.2

이 문서는 03.new_valuation 시스템을 신규로 구축하거나 다른 PC에 동일하게 재구축할 때 필요한 전체 절차를 다룬다.
현재 코드는 01.kr_valuation 운영 패턴을 계승하되, EPS 수집/점수 체계/일일 산출물 자동화가 강화된 상태다.

주의:
- 본 시스템은 투자 의사결정 보조 도구이며 수익을 보장하지 않는다.
- 외부 데이터 소스(DART, yfinance, KRX, 웹 페이지) 변경 시 수집률과 결과가 달라질 수 있다.

---

## 1) 이번 버전에서 확정 반영된 핵심 개발 내용

### 1-1. 운영 구조
- 일일 실행과 캐시 갱신을 분리했다.
  - 일일: preprocess_daily_updates.py -> build_daily_report.py
  - 주기 갱신: refresh_eps_cache.py, refresh_assumptions.py
- PowerShell 래퍼(run_daily.ps1, run_eps_cache_refresh.ps1)가 사용자 환경변수를 로드한 뒤 Python 스크립트를 호출한다.

### 1-2. EPS 정책
- EPS 우선순위: manual_forward_eps -> trailing_eps_dart -> consensus_eps_scrape -> forward_eps_auto
- 중립 프록시 강제 대체는 제거했다.
- EPS 결측 종목은 제외 대신 관찰로 남기고, suggested_weight_pct=0.0으로 리스크를 통제한다.

### 1-3. DART 연동 안정화
- corpCode.xml 기반 매핑 캐시(dart_corp_code_cache.csv) 사용
- DART 계정명/계정ID 패턴 + 당기순이익/주식수 fallback으로 EPS 추정
- 일일 전처리에서 당일 공시를 반영하여 eps_cache를 보강

### 1-4. 기술/밸류 점수 체계 개선
- 점수 100점 몰림 완화를 위해 기술/밸류 점수를 연속형으로 계산
- 기술점수는 추세(55), RSI(15), MACD(10), 거래량(10), 20일 돌파(10) 구조
- 액션 분류 기준:
  - 최종매수후보: total_score >= 75, above_ma200=1, breakout_20d_high=1, EPS 존재
  - 진입대기: total_score >= 65, above_ma200=1, EPS 존재
  - 관찰: total_score >= 50 또는 EPS 결측

### 1-5. 제외 정책 확정
- 종목명 필터는 REIT(리츠)만 제외로 운영
- 인프라/금융은 기본적으로 유지

### 1-6. 신규 자동 산출물(일일)
- 기존 리포트 3종 + 최종매수후보 분석 파일 4종 자동 생성
  - 최종매수_30일타임라인_YYYY-MM-DD.csv
  - 최종매수_전일비교_YYYY-MM-DD_vs_YYYY-MM-DD.csv
- 과거 레거시 파일 up_final_buy_timeline_10d_*.csv는 일일 실행 시 자동 정리

## 3) 신규 PC 재구축 절차 (상세)

### 3-1. 사전 준비
1. Python 3.12 이상 설치
2. 작업 폴더 준비
3. 네트워크 허용(증권/재무 데이터 접근 가능)

### 3-2. 가상환경 구성
```powershell
Set-Location "d:\00.개발\03.new_valuation"
python -m venv ..\.venv
..\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r .\requirements.txt
```

### 3-3. 실행 Python 경로 고정(권장)
```powershell
[Environment]::SetEnvironmentVariable(
  'UP_VALUATION_PYTHON',
  'd:/00.개발/.venv/Scripts/python.exe',
  'User'
)
```

### 3-4. DART API 키 등록(필수)
```powershell
Set-Location "d:\00.개발\03.new_valuation"
powershell -ExecutionPolicy Bypass -File .\set_dart_api_key_env.ps1 -Scope User
```

### 3-5. KRX 로그인 계정 등록(선택, 권장)
```powershell
Set-Location "d:\00.개발\03.new_valuation"
powershell -ExecutionPolicy Bypass -File .\set_krx_login_env.ps1 -Scope User
```

설명:
- KRX_ID/KRX_PW가 없으면 pykrx 연동은 비활성화되며 fallback 소스를 사용한다.

### 3-6. 초기 데이터 생성
```powershell
Set-Location "d:\00.개발\03.new_valuation"
.\run_eps_cache_refresh.ps1 --force --limit 100
.\run_assumptions_refresh.ps1
.\run_daily.ps1 --limit 100 --period 6mo
```

### 3-7. 전체 운영 전환
```powershell

.\run_eps_cache_refresh.ps1 --force
```

## 4) 일일 파이프라인 상세 (실제 동작)

### 4-1. preprocess_daily_updates.py
- DART 당일 공시 스캔
- 주요 이벤트 반영으로 eps_cache 보정
- 주식수 변동 리밸런싱
- forward EPS 자동 채움

### 4-2. build_daily_report.py
- 유니버스 로드 및 제외 필터 적용(REIT only)
- 가격/지표 수집(yfinance)
- EPS 소스 우선순위 적용
- 밸류/기술/종합 점수 계산
- 액션 분류 및 비중 산출
- 결과 CSV 저장
- 최종매수후보 30일 타임라인/전일 diff 생성
- 레거시 10일 파일 자동 삭제

## 5) 산출물 명세 (운영 기준)

### 5-1. 기본 산출물
- 상세리포트_YYYY-MM-DD.csv
  - 상세 원본(전체 종목)
- 관심종목요약_YYYY-MM-DD.csv
  - 사람이 매일 확인하는 핵심 요약
- 진입후보요약_YYYY-MM-DD.csv
  - 최종매수후보 + 진입대기 집합

### 5-1-b. 문서 자산(고정 파일)
- 문서/up_column_dictionary_ko.csv
  - 컬럼 사전(파일이 없을 때만 자동 생성)
- 문서/column_dictionary_archive/up_column_dictionary_ko_YYYY-MM-DD.csv
  - 기존 output의 날짜별 컬럼사전 이관본

### 5-2. 최종매수후보 확장 산출물
- 최종매수_30일타임라인_YYYY-MM-DD.csv
  - 당일 최종매수후보 종목별 최근 30거래일 타임라인
  - 컬럼: date, name, ticker, market, close, prev20_high, breakout_20d_high, volume_ratio_20d
- 최종매수_전일비교_YYYY-MM-DD_vs_YYYY-MM-DD.csv
  - 전일 대비 유지/신규/이탈 및 점수/신호 변화

### 5-3. 빈 파일 정책
- 당일 최종매수후보가 0개여도 timeline_30d 파일은 빈 스키마로 생성한다.
- diff 파일은 전일 상세 리포트가 존재할 때 생성된다.

## 7) 품질 검증 체크리스트

## 8) 트러블슈팅 (실무 빈도 높은 항목)

### 8-1. PermissionError: output CSV 권한 거부
원인:
- 엑셀 등에서 동일 파일을 열어둔 상태

해결:
1. 열린 파일 닫기
2. run_daily.ps1 재실행

### 8-2. DART 수집률 저하
점검:
```powershell
[Environment]::GetEnvironmentVariable('DART_API_KEY', 'User')
```
추가 점검:
- dart_corp_code_cache.csv 재생성 필요 여부
- 일시적 API 장애 여부

### 8-3. pykrx 로그인 실패
점검:
```powershell
[Environment]::GetEnvironmentVariable('KRX_ID', 'User')
[Environment]::GetEnvironmentVariable('KRX_PW', 'User')
```
설명:
- 미설정 시 pykrx 경로는 자동 비활성화되고 fallback 경로를 사용한다.

### 8-4. Python 실행기 탐지 실패
해결:
```powershell
[Environment]::SetEnvironmentVariable('UP_VALUATION_PYTHON','d:/00.개발/.venv/Scripts/python.exe','User')
```
