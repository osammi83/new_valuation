# 03.new_valuation 프로그램 설명 및 운영 흐름

**작성일**: 2026-04-25  
**목적**: `03.new_valuation` 폴더의 프로그램을 AI가 재분석할 수 있도록, 각 파일의 기능과 실행 구조, 운영 방식, 데이터 흐름을 상세히 정리한다.

---

## 1. 시스템 개요

`03.new_valuation`은 한국 주식 종목을 대상으로 하는 **CSV 기반 일일 밸류에이션/추천 엔진**이다. 핵심 철학은 다음과 같다.

- 데이터는 DB가 아니라 CSV 파일로 관리한다.
- 일일 실행은 PowerShell 오케스트레이션이 담당한다.
- Python은 계산 엔진, PowerShell은 환경/스케줄/실행 제어를 맡는다.
- EPS, 섹터, 기술지표, 레짐, 비중, 액션을 한 번에 계산해 일일 산출물을 생성한다.
- 월간 작업은 캐시 재생성, assumptions 동기화, 자동화 점검으로 분리한다.

이 구조는 운영이 단순하고 Git diff로 변경 추적이 쉽다는 장점이 있다. 반면, 규칙과 데이터 정합성이 깨지면 바로 결과에 반영되므로 운영 문서와 검증 스크립트가 중요하다.

---

## 2. 실행 방식 요약

### 2-1. 일일 실행

일일 핵심 진입점은 `run_daily.ps1`이다.

실행 흐름은 다음 순서다.

1. `up_valuation_config.json` 읽기
2. Python 실행 파일 해석
3. `DART_API_KEY`, `KRX_ID`, `KRX_PW` 환경변수 로딩
4. `pip install -r requirements.txt`
5. `preprocess_daily_updates.py` 실행
6. `refresh_assumptions.py` 실행
7. `build_daily_report.py` 실행
8. 설정에 따라 `upload_to_google_drive.py` 실행

운영상 중요한 점은, 현재 로그 기준으로 `build_daily_report.py`가 **중복 호출되는 흔적**이 있다. 파일 내부를 다시 보면 실제로 한 번 더 호출되는 라인이 존재할 수 있으므로, 후속 개선 대상이다.

### 2-2. 월간 실행

월간 작업은 2개로 분리되어 있다.

- `run_eps_cache_refresh.ps1`
- `run_assumptions_refresh.ps1`

이 두 스크립트는 Windows Task Scheduler로 등록되며, 각각 EPS 캐시와 assumptions 정합성을 갱신한다.

### 2-3. 수동 실행

수동 테스트는 보통 다음 순서로 한다.

- `run_eps_cache_refresh.ps1 --force --limit N`
- `run_assumptions_refresh.ps1 --limit N`
- `run_daily.ps1 --limit N --period 6mo`

`--limit`는 소량 테스트용, `--period`는 yfinance 히스토리 길이 조절용이다.

## 3. 파일별 상세 설명

### 3-1. `run_daily.ps1`

일일 운영의 메인 오케스트레이터다.

#### 구현 내용
- `up_valuation_config.json`에서 Python 경로와 업로드 옵션을 읽는다.
- `UP_VALUATION_PYTHON` 또는 `py -3`, `python`을 이용해 실행기를 찾는다.
- `DART_API_KEY`, `KRX_ID`, `KRX_PW`를 현재 세션에 주입한다.
- requirements를 설치한 뒤 Python 스크립트들을 순차 실행한다.
- Google Drive 업로드 조건이 맞으면 후처리 업로드를 시도한다.

#### 출력/역할
- 직접 CSV를 만들지는 않지만, 전체 파이프라인의 출발점이다.
- 실패 시 일일 산출물이 생성되지 않으므로 가장 중요한 실행 진입점이다.

#### 운영 포인트
- 이 파일이 곧 운영 표준이다.
- 실행 순서가 바뀌면 섹터/손실/EPS 정합성이 깨질 수 있다.
- 현재는 build 단계 중복 호출 가능성도 점검해야 한다.

---

### 3-2. `run_eps_cache_refresh.ps1`

EPS 캐시만 따로 갱신하는 월간 래퍼다.

#### 구현 내용
- Python 경로를 해석한다.
- requirements를 설치한다.
- `refresh_eps_cache.py`를 호출한다.

#### 역할
- DART/Naver 기반 EPS 원천을 월간 정리한다.
- 메인 일일 파이프라인에서 EPS 캐시를 재수집하지 않고 기존 캐시를 사용하도록 분리한다.

---

### 3-3. `run_assumptions_refresh.ps1`

`assumptions.csv` 동기화 전용 래퍼다.

#### 구현 내용
- Python 경로를 해석한다.
- requirements를 설치한다.
- `refresh_assumptions.py`를 실행한다.

#### 역할
- universe 신규 편입/제외를 assumptions에 반영한다.
- EPS 캐시의 섹터 정보를 assumptions에 보강한다.

---

### 3-4. `install_automation.ps1`

초기 설치 자동화 스크립트다.

#### 구현 내용
- Python 경로를 자동 탐색한다.
- 못 찾으면 사용자 입력을 받아 저장한다.
- `up_valuation_config.json`을 생성한다.
- `setup_scheduled_tasks.ps1`을 호출해 Task Scheduler 작업을 등록한다.

#### 역할
- 새 PC, 새 환경, 재설치 상황에서 한 번에 설정하기 위한 엔트리 포인트다.

---

### 3-5. `setup_scheduled_tasks.ps1`

Windows Task Scheduler 등록 스크립트다.

#### 구현 내용
- `schtasks`로 3개 작업을 만든다.
  - `UPValuation-Daily`
  - `UPValuation-EPS-Monthly`
  - `UPValuation-Assumptions-Monthly`
- 각각 `run_daily.ps1`, `run_eps_cache_refresh.ps1`, `run_assumptions_refresh.ps1`를 실행한다.

#### 운영 의미
- 이 프로젝트의 “자동화”는 결국 이 파일이 책임진다.
- PowerShell → schtasks → PowerShell/Python 체인으로 동작한다.

---

### 3-6. `remove_scheduled_tasks.ps1`

등록된 작업을 제거하는 정리용 스크립트다.

#### 역할
- 스케줄러 삭제
- 환경 재구성 또는 배포 해제 시 사용

---

### 3-7. `set_dart_api_key_env.ps1`

DART API 키를 환경변수로 저장하는 도구다.

#### 구현 내용
- 사용자 입력을 받아 `DART_API_KEY`를 설정한다.
- 현재 세션과 User/Machine 범위에 저장한다.
- 프로젝트 파일에는 키를 쓰지 않는다.

#### 운영 의미
- DART EPS 수집과 일일 공시 스캔의 전제조건이다.

---

### 3-8. `set_krx_login_env.ps1`

KRX ID/PW를 환경변수로 설정하는 도구다.

#### 구현 내용
- ID는 일반 입력, PW는 SecureString으로 입력받는다.
- `KRX_ID`, `KRX_PW`를 세션/영구 환경변수에 저장한다.

#### 운영 의미
- pykrx 기반 조회, 주식수/시장데이터 보강에 필요하다.

---

### 3-9. `check_drive_config.ps1`

Google Drive 업로드 설정 검증 스크립트다.

#### 확인 항목
- `up_valuation_config.json` 존재 여부
- JSON 형식 유효성
- `pythonPath` 유효성
- `googleDriveFolderId` 형식
- 서비스 계정 JSON 존재 및 필드
- Google API 라이브러리 설치 여부

#### 운영 의미
- 업로드 기능을 켜기 전에 반드시 점검해야 하는 진단 도구다.

---

### 3-10. `preprocess_daily_updates.py`

일일 전처리의 핵심 Python 모듈이다.

#### 구현 내용
- DART 당일 공시를 스캔한다.
- 잠정실적/실적/영업/매출 관련 공시 종목을 찾는다.
- 주식수 변동을 감지하고 EPS를 리밸런싱한다.
- `forward_eps_auto`를 보강한다.
- 필요 시 `universe.csv`를 재구성한다.

#### 입력/출력
- 입력: `universe.csv`, `assumptions.csv`, `eps_cache.csv`, DART/KRX 환경변수
- 출력: 주로 `eps_cache.csv` 갱신

#### 역할
- 일일 리포트 계산 전에 데이터 오염을 줄이는 전처리 계층이다.

---

### 3-11. `refresh_eps_cache.py`

EPS 캐시의 본체다.

#### 구현 내용
- DART API에서 EPS를 우선 수집한다.
- Naver Finance를 스크래핑해 trailing/consensus EPS와 섹터를 보조 수집한다.
- corpCode 캐시(`dart_corp_code_cache.csv`)를 재사용한다.
- shares_outstanding를 추정/보정한다.
- 제한 갱신 시 기존 캐시와 병합한다.

#### 입력/출력
- 입력: `universe.csv`, DART API, KRX/pykrx, Naver HTML
- 출력: `eps_cache.csv`, `dart_corp_code_cache.csv`

#### 운영 의미
- 월간 갱신 작업으로 분리되어 있고, 일일 파이프라인은 이 파일을 다시 긁지 않는다.

---

### 3-12. `refresh_assumptions.py`

assumptions 정합성 보정기다.

#### 구현 내용
- `universe.csv`를 기준으로 `assumptions.csv`를 재정렬/동기화한다.
- DEFAULT_ASSUMPTION 값으로 빈 칸을 채운다.
- `eps_cache.csv`의 `naver_sector`를 읽어 `sector_group`을 자동 보정한다.

#### 입력/출력
- 입력: `universe.csv`, `assumptions.csv`, `eps_cache.csv`
- 출력: `assumptions.csv`

#### 운영 의미
- 현재 Day 1 이후 핵심 개선의 하나로, 섹터가 `기타`에서 실제 업종으로 복원된다.

---

### 3-13. `build_daily_report.py`

가장 중요한 메인 분석 엔진이다.

#### 구현 내용
- 가격, 거래량, 기술지표, EPS, 밸류에이션, 시장 레짐을 종합한다.
- `total_score`와 `combined_action`을 계산한다.
- `suggested_weight_pct`를 산출한다.
- 시장 레짐은 MA/HV20/ROC60 기반 3신호 체계로 판단한다.
- compact/full 출력 모드를 지원한다.
- 30일 타임라인, 전일 비교, 핵심근거, 컬럼 사전 문서를 만든다.

#### 주요 산출물
- `output/상세리포트_YYYY-MM-DD.csv`
- `output/종목선정_핵심근거_YYYY-MM-DD.csv`
- `output/최종매수_30일타임라인_YYYY-MM-DD.csv`
- `output/최종매수_전일비교_YYYY-MM-DD_vs_YYYY-MM-DD.csv`
- full 모드 시 추가 파일 여러 개

#### 운영 메모
- 이 파일이 사실상 제품 본체다.
- 점수와 액션, 비중이 여기서 모두 결정된다.
- 현재는 레짐 로그가 출력되도록 강화되어 있다.

---

### 3-14. `upload_to_google_drive.py`

일일 CSV를 Google Drive로 올리는 통합 업로더다.

#### 구현 내용
- 서비스 계정 JSON과 folder id를 읽는다.
- output 폴더에서 당일 파일을 수집한다.
- 같은 이름의 파일이 있으면 update, 없으면 create 한다.

#### 운영 의미
- 외부 공유 또는 백업용 배포 경로다.
- 설정이 비어 있으면 안전하게 스킵한다.

---

### 3-15. `refresh_daily_preprocess.py`

레거시 또는 대체 전처리 경로로 보이는 통합형 Python 파일이다.

#### 구현 내용
- 시장 레짐 스냅샷을 `market_regime.csv`로 저장한다.
- EPS 캐시를 기존 값과 병합한다.
- DART 공시 및 스크래핑 기반 갱신을 수행한다.

#### 해석
- 현재 메인 실행 경로는 `run_daily.ps1 → preprocess_daily_updates.py → refresh_assumptions.py → build_daily_report.py`이므로, 이 파일은 **실질적인 메인 경로보다는 대체/구버전 참조용**으로 보는 편이 맞다.

---

### 3-16. `day1_validation.py`

Day 1 개선사항을 점검하려고 만든 초기 검증기다.

#### 특징
- 상세리포트 컬럼명을 구버전 기준으로 읽으려 한다.
- 현재 스키마와 안 맞으면 실패할 수 있다.

#### 해석
- 문서상 기록용으로는 의미가 있지만, 실무 기준 검증기는 아니다.

---

### 3-17. `day1_validation_fixed.py`

Day 1 검증기의 수정판이다.

#### 구현 내용
- 한글 컬럼명을 기준으로 읽는다.
- 섹터 다양성, 손실 플래그, 액션-비중 정합성, 레짐 분포를 확인한다.

#### 운영 의미
- 현재 구조에서는 이 파일이 실사용 검증기다.
- Day 1 개선사항의 성공 여부를 확인하는 핵심 도구다.

## 4. 데이터 파일과 설정 파일

### 핵심 데이터 파일

| 파일 | 역할 |
|---|---|
| `output/상세리포트_*.csv` | 전체 상세 리포트 |

## 5. 운영 구조

### 일일 운영

아침 자동 실행 후 확인할 것:

1. `output/`에 최신 날짜 파일이 생겼는지 확인
2. `상세리포트_*.csv`와 `종목선정_핵심근거_*.csv`를 우선 확인
3. `최종매수_30일타임라인_*.csv`로 추세 지속 여부 확인
4. `최종매수_전일비교_*.csv`로 신규/이탈/유지 확인
5. `warn_flags`, `brief_reason`, `선정의견`을 보고 실제 검토 대상 추리기

### 월간 운영

월 1회 또는 수동으로:

- EPS 캐시 갱신
- assumptions 동기화
- 섹터/업종 보정 상태 확인
- 필요시 DART/Google Drive 설정 검증

### 설정 의존성

- DART 데이터: `DART_API_KEY`
- KRX 데이터: `KRX_ID`, `KRX_PW`
- Python 경로: `UP_VALUATION_PYTHON` 또는 `up_valuation_config.json`
- Drive 업로드: `enableGoogleDriveUpload`, `googleDriveFolderId`, `googleServiceAccountJsonPath`

## 6. 후속 AI 분석 요청용 체크포인트

이 문서를 기반으로 AI에게 다음 분석을 요청하면 좋다.

1. `run_daily.ps1`의 중복 호출/실행 순서 이상 여부 점검
2. `build_daily_report.py`의 점수식과 액션 기준 재설계
3. 섹터/레짐/손실 플래그 정합성 검증
4. `refresh_daily_preprocess.py`와 현재 메인 경로의 중복 기능 정리
5. `day1_validation.py`와 `day1_validation_fixed.py`의 역할 통합 여부
6. `market_regime.csv`를 실제 운영 경로에 넣을지 여부
7. Google Drive 업로드를 운영 필수로 둘지 선택 사항으로 둘지
8. 향후 DB 전환 없이 CSV 구조를 유지하면서 feature store를 확장할 방법

## 7. 요약

이 프로젝트는 이미 단순한 스크립트 모음이 아니라, **운영 가능한 일일 리서치 파이프라인**이다. 핵심은 다음 3개다.

- PowerShell이 실행과 자동화를 책임진다.
- Python이 계산과 파일 생성을 책임진다.
- CSV가 데이터의 단일 저장소다.

따라서 추가 개발을 요청할 때는 “새 기능을 어디에 넣을지”보다, **어떤 파일이 어떤 책임을 가져야 하는지**를 먼저 정의하는 것이 가장 중요하다.
